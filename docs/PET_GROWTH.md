# 书宠的人物成长机制

> 这份文档只讲**一件事**: 读者读的书, 怎么一点点变成书宠身上的东西。
> 所有数字都能在代码里找到出处 (每节末尾标了文件与常量名), 改机制时先改这里再改代码。
>
> 落点: `src/recto/pet/` · 页面: `/pet/` · 数据: `<data_dir>/pet/{char.json,chronicle.json,pet.sqlite}`

---

## 0. 一张图

```
                        ┌─ 阅读时长 (分钟) ──┐
读者在阅读器里读书 ─────┤                    ├─→ 修为 ─→ 等级 ─┬─→ 技能上限 (每门练到几级)
                        └─ 章节推进 / 划线 ──┘                 ├─→ 潜能点 ─→ 六项根骨
                                                              └─→ 声望 / 先天属性 / 品级
                                     │
                                     ├─ 语料遭遇 (书里的词) ─→ 这一趟是什么事 (斗/会/观/学/救/行)
                                     │                        └─→ d20 遭遇 + 路上的坎
                                     │                              │
                                     │                              ├─→ 用过的功夫 ─→ 熟练度 ─→ 技能等级
                                     │                              └─→ 伤 / 内力消耗 / 声望
                                     └─→ 说书人 (模型) 写出「第 N 回」+ 判词
```

三个互相独立的东西，别混：

| 概念 | 是什么 | 从哪来 |
|---|---|---|
| **等级 (Lv)** | 江湖份量: 决定技能上限、气血上限、品级 | 修为够就升 |
| **修为 (exp)** | 读书攒下的内功底子 | 后台推演判定 (按阅读量与遭遇) |
| **技能等级** | 具体某门功夫练到第几层 | **只由熟练度决定** |

## 1. 时间: 故事里的日子

| 量 | 值 | 说明 |
|---|---|---|
| 故事内一天 | **0.6 分钟阅读** | 六分钟现实阅读 = 故事里十天; 一小时 = 一百天 |
| 出江湖 | 12 岁 | |
| 退隐 | 80 岁 | 到岁数写「终回」, 等读者确认传承 |
| 一年 | 365 天 | 不闰 |
| 一趟游历 | 攒够 **10 个故事日** (≈6 分钟阅读) | `days_per_adventure` |
| 时钟闸 | 一回合最多走 **300 天** | 存档被还原 / 时长表被清理时防"凭空走过一百多天" |

故事内的日子**不单独计数** —— 它就是累计陪读分钟除出来的 (`minutes / 0.6`)。
所以删书、清空时长表都不会让时间倒流 (只增不减)。

出处: `pet/life.py` `MINUTES_PER_STORY_DAY` / `START_AGE` / `RETIRE_AGE`；
`pet/chronicle.py` 的 `cfg()` (`days_per_adventure` / `max_days_per_cycle`)。

## 2. 修为与等级

### 2.1 修为从哪来

只有一条: **后台推演判定** (`growth.award_judged`)。模型看到这段时间的读书记录
(读了多久 / 推进几章 / 划了几条线 / 撞见哪些语料), 按 `pet/skills/chronicle.md`
的口径给一个数, 代码只做夹逼:

| 夹逼项 | 上限 |
|---|---|
| `exp` | `故事内天数 × 3.2`，且 ≤ 3000 |
| `pot` (潜能) | 3 |
| `fame` (声望) | 20 |
| `morality` (心性) | ±5 |

**只增不减**: 一切负数当 0。读者这几天读得少, 就是少, 不倒扣。

> 为什么分钟不直接换修为: 分钟只是证据之一。读同一本书翻来覆去 reread 与啃新章,
> 攒下的东西不一样; 划线、批注、语料遭遇都该算进去 —— 那是判词的事。
> 例外: 陪读心跳会把分钟记进 `minutes` (推进经脉与故事日), 但**不给修为**,
> 见 `companion.credit_reading_minutes(grant_exp=False)`。

### 2.2 升级曲线

```
升到下一级需要:  exp_needed(L) = 24 + 10 × (L − 1)
```

| 等级 | 升下一级 | 升到该级累计 |
|---|---|---|
| 1 | 24 | 0 |
| 5 | 64 | 208 |
| 12 | 134 | 814 |
| 24 | 254 | 3 400 |
| 48 | 494 | 13 800 |

一回合 (十来分钟阅读) 一般给 15~35 点，所以**头几级一两回就升, 后面慢慢变慢**。
曲线改过两次：`100 × L²` (太陡, 十几回不动) → `24 + 10(L−1)` (现行)。

### 2.3 升级给什么

| 每升 1 级 | 量 | 去处 |
|---|---|---|
| 潜能点 | +3 | 玩家自己分配到六项根骨 |
| 声望 | +5 | 品级、门派、故事里的名头 |
| 先天属性 | 悟性每 3 级 +1 / 根骨每 6 级 +1 | 直接进实际属性 (封顶 30) |
| 技能上限 | +1 格左右 | 见 §3.3 |

存量修为可以补兑现: `python3 -m recto.cli pet settle`（幂等, 曲线改过之后用）。

出处: `pet/charsheet.py` `exp_needed` / `level_exp`；`pet/growth.py`
`POT_PER_LEVEL` / `FAME_PER_LEVEL` / `BORN_ON_LEVEL` / `settle_levels`。

## 3. 技能: 只由熟练度决定

### 3.1 熟练度从哪来

| 来源 | 一次几拍 | 每拍几点 |
|---|---|---|
| 自己出手 (主修兵刃/拳脚) | 每拍 | **3** |
| 使一次绝招 | 每次 | **4** |
| 被攻一拍 (拆招 = 基本招架) | 每拍 | **1** |
| 过了一道坎 | 每道 | **9** |
| 坎没过 | 每道 | **6** (败也是练) |
| 判词点名「这一趟悟到了」 | 每回最多 1 门 | **25** |

```python
PROF_PER_LEVEL = 120          # 满 120 点升一级
PER_SKILL_PER_CYCLE_CAP = 50  # 一趟里同一门最多攒 50 点实战熟练度
```

一场十来拍的遭遇大约折 60~70 点 (摊在 2~4 门功夫上), 加两道坎 ≈ 15 点。
所以**主修那门大约 2~3 趟升一级**；一小时阅读 = 十趟 ≈ 主修涨 3~4 级 (受上限约束)。

判词那一笔 25 点是**另一份预算**, 不吃每趟 50 的封顶 —— 它回答的是
"这一趟没被用到、但它想通了的那一门"。

### 3.2 升级规则

- 熟练度满 `PROF_PER_LEVEL` (120) → 该门 **+1 级**, 余数保留
- 一次攒很多可以连升, 但**到上限就停**
- 到上限后**不再吃熟练度** (停在满格) —— 否则一升级就"本来就快满",
  读者永远看不出"还得再练"

### 3.3 技能上限: 与等级挂钩

```
skill_cap(等级, 悟性) = floor( (level_exp(等级) × 10) ^ (1/3) + 1 ) × (10 + 悟性) / 40
```

- `level_exp(L)` = 升到 L 级所需的**累计**修为 (曲线台阶)
- 外形仍是侠客行那条 `(EXP×10)^(1/3)+1`, 只是 EXP 换成**等级对应的台阶**
- 悟性打折: 悟性 10 → 半折, 悟性 30 → 原值
- 再按禀赋的 `skill_cap_pct` 加减百分比, 最后与 `skill.cap` (单门硬顶) 取小

| 等级 (悟性 18) | 每门最高 |
|---|---|
| 1 | 2 |
| 6 | 8 |
| 12 | 14 |
| 24 | 21 |
| 48 | 30 (硬顶) |

**为什么换成等级**: 旧口径拿"一辈子累计修为"算上限, 等级只是个副产品 ——
界面上写着 Lv 却对本事没有约束力; 而且升级把零头清掉时上限会抖。
现在上限**只在升级时抬一格**, 玩家一眼能对上「我 12 级, 所以每门练到 14 级」。

### 3.4 例外: 基本内功按分钟长

`AUTO_SKILL = jibenneigong`, 每 `300` 分钟陪读 **+1 级** (五小时一级)。
它是"读书如打坐"的底子, 走分钟不走熟练度 —— 但同样受等级上限约束。

出处: `pet/charsheet.py` `PROF_PER_LEVEL` / `add_practice` / `skill_cap` / `cap_for`；
`pet/growth.py` `PRACTICE` / `practice_from` / `practice_judged` / `AUTO_SKILL*`；
`pet/duel.py` 的 `usage` (出手/绝招/被攻) 与 `pet/checks.py` 的 `skill` 字段。

## 4. 六项根骨与派生数值

### 4.1 根骨

| 项 | 起 | 封顶 | 作用 |
|---|---|---|---|
| 臂力 (li) | 10 | 30 | 伤害 |
| 根骨 (gen) | 10 | 30 | 气血、护体、豁免 |
| 悟性 (wu) | 10 | 30 | **技能上限**、心思 |
| 身法 (shen) | 10 | 30 | 命中、闪避、先攻、暴击 |
| 定力 (ding) | 10 | 30 | 心神、交涉 |
| 耐力 (na) | 10 | 30 | 精力 |

总和封顶 180。实际值 = 基础 (10 + 潜能分配) + 先天 (升级偶得) + 门派加成 + 禀赋加成,
每项封顶 30。**门派加成是派生值**, 叛门立刻收回 (存档只存基础值)。

### 4.2 衍生

```
气血上限 = 20 + 根骨×3 + 等级×2 + 最高内功等级 + 经脉加成
内力上限 = 最高内功等级×10 + 根骨×2
心神上限 = 20 + 定力×3 + 悟性×2
精力上限 = 根骨×5 + 耐力×5
```

气血/内力**当前值会被遭遇吃掉**, 上限永远实时算。调息按"现实分钟 / 60"折算:
每故事日回 18% 气血 / 45% 内力 (`restore`)。

出处: `pet/charsheet.py` `effective_attrs` / `derive` / `resources` / `restore`。

## 5. 这些数值在故事里怎么被用到

技能与根骨不是摆设 —— 每一次遭遇都按 d20 结算 (`pet/duel.py`, `pet/checks.py`):

| 环节 | 公式 (要点) |
|---|---|
| 先攻 | `d20 + 身法加值 + 轻功一半` |
| 命中 | `d20 + 根骨加值 + 主修技能加值 (+绝招加值 2)` vs 护体 AC |
| 护体 | `10 + 根骨加值 + 基本招架 + 轻功一小截 + 禀赋招架` |
| 伤害 | `兵刃骰 + 臂力加值×2 + 主修加值×2 + 8 − 卸力` |
| 暴击 | 掷出 `≥ 20 − 暴击//5` (骰面 20 也算) → 伤害骰掷两遍 |
| 大失败 (1) | 必不中 + 自伤 + 门户大开 (对方 +2) |
| 绝招 | 先付内力, 再掷运功检定; **骰出 1 才反噬**, 只是没过 = 招式没运成 |
| 定身 | 命中后对方掷根骨豁免 vs `8 + 招式加值`, 不过则定 N 拍 |
| 路上的坎 | `d20 + 对应根骨 + 对应技能 + 禀赋` vs 难度 (白检定可再试, 红检定一次定生死) |

所以"练了哪门功夫"直接决定"下一场打不打得过"。这也是 §3.1 的记账口径要按
**真用过的招**来算的原因: 战报里使了十二剑, 剑法就该动。

出处: `pet/charsheet.py` `d20_stats` / `derive()["combat"]`；`pet/d20.py`；`pet/duel.py`；`pet/checks.py`。

## 6. 门派 / 禀赋 / 经脉

- **入门**: 给本门内功、本门兵器、一路绝招各 1 级 + 一项根骨加成；叛门清声望与门忠
  (学过的招不收回)。
- **禀赋 (性情)**: 最多 6 条, 总分 ≤ 100 (黄 40 / 红 30 / 蓝 20 / 绿 10)。
  每条带 `mods` (命中/闪避/伤害/技能上限% …), 全部实时汇总进战斗数值。
- **经脉十层**: 按累计陪读分钟推进 (第一层 120 分钟 → 第十层 3900 分钟),
  通脉给五行亲和; 第 3 层另加六项根骨, 第 10 层绝招定身 +1。

出处: `pet/charsheet.py` `SCHOOLS` / `TRAITS` / `VEINS` / `trait_mods`。

## 7. 退隐与传承

- 到 80 岁 → 这一趟写「终回」(收手 → 看见那个人 → 递灯), 存档进 `life.stage = retiring`,
  此后不再长大、不再出门。
- 读者点头 (`POST /pet/api/char/inherit`, 必须 `confirm: true`) 才换人:
  上一代存档进 `lineage/genNN-名字.json`, 新人 12 岁、零分钟, 带家学
  (最高技能 30%, 最少 1 级) / 声望 1/20 / 心性一半 / 3 点潜能。
- 传承后 `chronicle.json` 的故事日归零, 否则"新一代"永远出不了门。

出处: `pet/life.py` (`HEIR_SKILL_SHARE` / `HEIR_POT` / `HEIR_TYPES`)、`pet/reborn.py`。

## 10. 已知边界 / 待定

- **判定的二次影响**: 掷出来的结果现在影响成长与开场的坎, 但**不改当晚故事的走向**
  (故事只照写)。要不要让"打输了"改变剧情, 未定。
- **重读同一本书**: 没有打折规则, 由判词按章节推进量自己掌握。
- **每日陪读上限**: 没有 (只有单次 480 分钟的封顶)。
- **觉醒点 (`wish`)**: 没有来源。
- **熟练度的"退步"**: 一律不扣 —— 长期不练也不会掉级 (与"只增不减"同一条规矩)。

## 11. 交手节奏 / 绝招出手 / 磨招 (2026-11-17)

**为什么会觉得"剑招用得不多"**: 三处都在压它, 不是巧合。

1. **交手太短**。旧口径对手气血与伤害各自独立归一, 对手一拳能打掉三成半
   气血 —— 实测一场四拍就收场, 绝招 (每回合只有 45% 会想起使) 常常一次都没放。
   现在气血与出伤按**"几拍见血"**配对定: 以"我方平均一击"为单位定对手气血、
   以"我方气血"为单位定对手出伤, 双方各约五拍倒, 交手落在 10~20 拍
   (中位数 14~17)。分母同时夹在"与书宠同量级" (0.75~1.28 倍气血) 里,
   高攻低血的 build 不会招来血量翻倍的对手。
2. **归一之后拆账没跟着改**。`_normalize_foe_stats` 只改 `attack` 数值, 掷骰却仍读
   pseudo 人物的 `attack_parts` —— 面板写"命中 +8", 实际按 +14 打, 八十场只赢五场。
   现在归一后**重写拆账** (一条 `对手的武艺`), 并把护体与命中**反向**浮动:
   更难打中的对手, 出手也相应更少。(顺带: 兵刃骰文本 `1dX+N` 与 flat 同步重算。)
3. **使守势类绝招等于白扔一拍**。旧写法 `defend/evade/heal/buff` 使完直接 return,
   少打一下 (约 14 点) 换来三成减伤 (约 4 点) —— 算下来永远是亏的。
   现在出招之后**照旧递一手** (不再整拍作废), 守势变成"守中带攻"。
   选招也按战况 (血薄→守/疗, 对方还硬→控, 将倒→补刀), 同一场使过的招降权,
   两门绝招都会露面 (实测四十场: 28 : 61, 旧写法永远是 rate 最高的那门)。

**「学」类那一趟自己磨招** (`growth.drill`, 每趟绝招 +26 / 主修兵器 +20):
绝招的熟练度本来只在交手时记得上, 而交手本来就少 —— 不给它一条自己练的路,
那门功夫一辈子停在入门那一级。没学过的招不会被凭空点出来; 练到上限就不再涨。

**故事要写出招式名**: `moves` 非空而正文一个招式名都没点时, 稿子会被打回重写一次
(`chronicle._moves_in_body`), 重写仍没点则在账上记 `duel_omitted`。
招式是书宠身上唯一"能被看见"的本事, 使了却不出名, 等于没使。

验收: `tests/test_pet_duel_balance.py` (20 项: 拆账归一 / 拍数中位数 / 胜负分布 /
两门绝招都出场 / 磨招幂等 / 招式名核验)。
