## 二、正文 A｜痛点叙事版（主推）

**手机读 40%，电脑上还是 3%**

这大概是多端读书最烦的事。

我的情况更碎：
📱 手机用掌阅
💻 电脑用自建书库
📄 墨水屏专门用来抄摘录

三个地方，三套进度，谁也不知道谁读到哪。
划线更别提了——手机上划的，电脑里根本没有。

后来我想明白一件事：
**问题不在"没同步"，在于两边的刻度根本不一样。**

一边记的是"读到全书 31.8%"
一边记的是"读到第 183 页"
换个字号、换个屏幕、换一次排版，页号全废。

所以我干脆自己写了一个服务：
**云阅 Recto**

它的做法很土也很稳——
所有端只交换两个数：**第几个文件 + 文件里第几个字节**。
页号、百分比、XPath，全都是这个数的投影，随时能重算。

于是：
✅ 手机上读到的位置，电脑打开就落在那儿
✅ 划线、书签、每天读了多久，双向同步
✅ 我改字号、改行距、换皮肤 —— 进度一动不动，因为排版不进同步通道
✅ 书架、阅读器、摘录、语料，全在一个端口里

我特别喜欢它对书的态度：
**不重排、不切片、不写回你的源文件。**
原书的字节就是坐标本身，动了它等于把进度全毁了。

现在我的日常是：
早上手机读两章 → 中午电脑打开接着读 → 晚上墨水屏把划的句子推回来。
进度只有一条线，划线只有一份账。

自托管这件事，做到最后其实不是为了"拥有数据"这四个字，
是为了**不被任何一端的排版决定我在哪一页**。

（部署要 Python 3.11 + 一个 lxml，一个进程一个端口，配置一个 toml。有在折腾 NAS 的应该十分钟能起来。）

## 三、正文 B｜技术自托管版（发给 Homelab / 折腾党）

**给自己的阅读留痕，建了个独立服务**

你大概也遇到过：
书在 A 处、进度在 B 处、划线在 C 处。
同步靠手动截图和记忆。

我做了个东西叫 **云阅 Recto**，只有一个职责：
**把"我读到哪、我划过什么、我读了多久"变成一条账。**

技术上有三个我比较满意的决定：

**1️⃣ 坐标只用一种**
`readPercent = (前面所有文档的字节 + 文档内偏移) / 全书字节`
所有端只交换"第几个文档 + 第几个字节"。
换排版不影响进度，换阅读器不影响进度，因为排版从来没进过同步通道。

**2️⃣ 书不动**
不重排、不切片、不写回源文件。
原书字节即坐标权威。改书 = 毁进度，所以干脆不碰。

**3️⃣ 状态全在本地**
`data/` 一个 sqlite + 一个 state 目录。
关掉网络照样读、照样记，联网后再对齐。
每本书的云身份写在它自己的边车 JSON（`书名.recto.json`）里——搬书库时连边车一起搬，映射就跟着书走。

功能面：
📚 卡片书架（封面 / 进度 / 划线数 / 阅读时长）
📖 内置阅读器：滚动 + 左右翻页、排版面板、目录分层折叠、划线书签
🔄 与掌阅双向同步：进度 / 划线 / 书签 / 每日阅读时长（时长按"取较大值"融合，不重复计）
🖊 墨水屏摘录接入（独立进程，端口按固件写死，不抢主服务）
🎨 六套皮肤，Material 3 骨架
🔍 语料关键词高亮：只上色，零 DOM 改动（不改一个字符，所以不影响坐标）

部署：Python ≥3.11 + lxml，一个进程一个端口（5015），一个 `config.toml`。
`bash run.sh start` 就完了。

一个人用的东西，所以也没做什么多用户权限、也不刮削元数据。
**它只管留痕，别的都交给已经好用的工具。**

## 四、正文 C｜短平快版（适合配图轮播）

**读书进度终于不用手动对了**

多端读书的人都懂：
手机一个进度，电脑一个进度，墨水屏一堆摘录，互不相认。

我给自己写了个服务，只干一件事：
**让"我读到哪"只有一条线。**

做法：所有端只交换「第几个文件 + 文件里第几个字节」。
百分比和页号都是它的投影 —— 所以改字号、改排版、换阅读器，进度都不动。

顺带把这些也接上了：
· 划线 / 书签双向同步
· 每天读了多久（两边取较大值，不重复计）
· 自建书架 + 内置阅读器
· 墨水屏摘录推回自己的账本

关键一条：**它不碰你的书。**
不重排、不切片、不写回源文件 —— 原书字节就是坐标本身。

自托管，一个进程一个端口，一个 toml。
一个人用，够干净。

## 八、（可选）长文版骨架 · 公众号 / 知乎

1. **困境**：多端阅读的三种刻度（页号 / 百分比 / XPath）
2. **一个反直觉的结论**：同步问题的本质是"刻度不统一"，不是"缺一个同步按钮"
3. **解法**：把原书字节当唯一坐标；排版只是投影
4. **由此推出的四条设计约束**：书不动 / 状态在本地 / 只前进 / 写前先体检
5. **功能全貌**（书架 / 阅读器 / 同步 / 摘录 / 高亮 / 皮肤）
6. **部署**：Python 3.11 + lxml，一个进程一个端口
7. **它不做什么**（不刮削、不多用户、不碰别人数据库）
8. **留给读者的问题**：你的阅读数据，愿意交给哪一端决定？
